# AGENTS.md — эксплуатация tamsyam

Этот файл для агентов, которые обслуживают уже развёрнутый tamsyam-server: обновляют версию, настраивают доступ к админке из LAN и VPN, меняют пароли и токены.

Первичная установка (Caddy, DNS, systemd) описана в [DEPLOY.md](DEPLOY.md). Там же лежат входные данные (`SERVER_SSH`, `CADDY_SSH`, `BASE_DOMAIN`) и откат. Значения переменных окружения описаны в [deploy/server.env.example](deploy/server.env.example). Если ты меняешь сам код, читай раздел «Разработка» в конце.

## Правила

- **Секреты не выводи.** Пароль админки, токены клиентов и Cloudflare-токен не печатай в чат и в логи, не передавай аргументами команд и не оставляй в истории shell. Пользователю называй файл, где лежит секрет, а не сам секрет. Исключение одно: новый пароль или токен, который пользователь попросил, показывается ему один раз в итоговом отчёте.
- **Перед правкой — бэкап.** Прежде чем менять `/etc/tamsyam/server.env`, скопируй его в `server.env.bak.$(date +%s)` с правами `600`.
- **Спроси пользователя перед:** рестартом в рабочее время (рестарт обрывает туннели), сменой пароля админки, отзывом токенов, изменением правил роутера и VPN, удалением `/var/lib/tamsyam`.
- **После каждого изменения проверяй.** Изменение считается сделанным, только когда прошли проверки из его раздела. Если проверка не прошла, верни бэкап и сообщи пользователю.

## Где что лежит

| Что | Где |
|---|---|
| Бинарник | `/usr/local/bin/tamsyam-server` |
| Настройки и пароль админки | `/etc/tamsyam/server.env` (`600`, root) |
| База: токены, статистика, закреплённые порты | `/var/lib/tamsyam/tamsyam.db` |
| Логи | `journalctl -u tamsyam-server` |
| Текущая версия | `curl -s -u "admin:$PW" https://<BASE_DOMAIN>/api/info` |

Пароль в переменную окружения shell читай из файла, а не набирай вручную:
```bash
PW=$(sed -n 's/^TAMSYAM_ADMIN_PASSWORD=//p' /etc/tamsyam/server.env)
```

## Обновление версии

1. Узнай последний релиз: `curl -s https://api.github.com/repos/Mi113r/tamsyam/releases/latest | grep tag_name`. Архитектуру сервера определи через `uname -m`: `x86_64` соответствует `amd64`, `aarch64` — `arm64`.
2. Скачай `tamsyam-server_<версия>_linux_<arch>.tar.gz` и `checksums.txt`, затем сверь хэш: `sha256sum -c --ignore-missing checksums.txt`.
3. Сохрани старый бинарник, установи новый и перезапусти:
   ```bash
   cp /usr/local/bin/tamsyam-server /usr/local/bin/tamsyam-server.prev
   tar -xzf tamsyam-server_*.tar.gz tamsyam-server
   install -m 755 tamsyam-server /usr/local/bin/tamsyam-server
   systemctl restart tamsyam-server
   ```
4. Посмотри примечания к релизу (`https://github.com/Mi113r/tamsyam/releases`). Если там появились новые переменные, добавь их в `server.env` по образцу `deploy/server.env.example`.

**Готово, когда:** `systemctl is-active tamsyam-server` выдаёт `active`, `curl -s https://<BASE_DOMAIN>/healthz` выдаёт `ok`, а `/api/info` показывает новую версию. Схема базы обновляется сама при старте. Если сервис не поднялся, верни `tamsyam-server.prev` и перезапусти.

## Как сервер определяет IP клиента

От этого зависят и беспарольный вход в админку, и `--allow`, и статистика. Прочитай раздел целиком, прежде чем трогать сети.

- Сервер видит IP того, кто подключился к нему напрямую. Если между клиентом и сервером стоит Caddy, сервер видит адрес Caddy.
- Настоящий адрес клиента Caddy передаёт в `X-Forwarded-For`. Сервер верит этому заголовку только от **доверенных прокси**: loopback (всегда) и адресов из `TAMSYAM_TRUSTED_PROXIES`.
- Если Caddy стоит на **том же** хосте, ничего настраивать не нужно. Если на **другом** хосте или в другом LXC, впиши его IP в `TAMSYAM_TRUSTED_PROXIES`. Иначе все запросы будут выглядеть как пришедшие от Caddy, а беспарольный вход отключится: сервер намеренно не пускает без пароля запросы, пришедшие через неизвестный прокси.
- Роутер может подменять адрес источника, и тогда сервер увидит не того клиента, которого ты ожидаешь:
  - **Hairpin NAT.** Если зайти из LAN на публичный домен, роутер может заменить адрес клиента на свой LAN-IP (например `10.1.1.1`) или на белый IP.
  - **NAT VPN-клиентов.** VPN-сервер на роутере (WireGuard или IPsec на Keenetic) часто маскирует клиентов под LAN-IP роутера. Тогда VPN-клиент выглядит как устройство из LAN.

Из-за этого адреса нужно **измерять**, а не угадывать. Порядок такой:

1. Запусти пробный туннель на любой машине с `ts` (установка описана в README): `python3 -m http.server 8000 --bind 127.0.0.1` и в другом терминале `ts http 8000 -s ipprobe --server https://<BASE_DOMAIN> --token <токен>` (о токене см. «Токены клиентов»).
2. Попроси пользователя открыть `https://ipprobe.<BASE_DOMAIN>/` с каждого типа устройства: из LAN по Wi-Fi, через VPN, через мобильный интернет.
3. Прочитай, какие адреса увидел сервер:
   ```bash
   curl -s -u "admin:$PW" https://<BASE_DOMAIN>/api/tunnels/ipprobe/requests | grep -o '"remote_ip":"[^"]*"'
   ```
4. Останови пробный туннель и `http.server`.

**Готово, когда** для каждого типа клиента записано, какой адрес видит сервер. Без этой таблицы к следующему разделу не переходи.

## Админка без пароля из LAN, с паролем из VPN и интернета

Используется `TAMSYAM_PRIVATE_NETWORKS`: список CIDR или IP через запятую. Из этих адресов админка открывается без пароля. Все остальные адреса вводят пароль. Исключений из списка задать нельзя, поэтому список составляется только из того, что можно пускать без пароля.

1. Возьми таблицу адресов из предыдущего раздела.
2. Составь список так, чтобы в него попали адреса LAN-клиентов и **не попал ни один** адрес, под которым видны VPN-клиенты или клиенты из интернета.
   - Если VPN-клиенты видны со своими адресами (например `10.8.0.x`), а LAN-клиенты со своими (`10.1.1.x`), впиши LAN-подсеть: `10.1.1.0/24`.
   - Если VPN-клиенты видны под LAN-IP роутера, этот IP не должен попасть в список. Перечисли узкие подсети без него (например `10.1.1.128/25`, если DHCP раздаёт адреса оттуда, а роутер `10.1.1.1`) или конкретные IP устройств. Другой вариант — с согласия пользователя отключить на роутере NAT для VPN.
   - Если LAN-клиенты через hairpin видны как белый IP или IP роутера, беспарольный вход по домену из LAN безопасно сделать нельзя. Предложи пользователю split-DNS: в LAN домен резолвится прямо в Caddy, тогда адрес клиента сохраняется.
3. Если Caddy на другом хосте, задай `TAMSYAM_TRUSTED_PROXIES=<IP Caddy>`.
4. Запиши значения в `server.env` (с бэкапом) и выполни `systemctl restart tamsyam-server`.

**Готово, когда все проверки дали ожидаемый ответ** (`200` — пустило без пароля, `401` — спросило пароль):

| Откуда | Команда | Ожидается |
|---|---|---|
| Устройство из LAN | `curl -s -o /dev/null -w '%{http_code}\n' https://<BASE_DOMAIN>/api/info` | `200` |
| VPN-клиент (пусть выполнит пользователь или открой в браузере) | то же | `401` |
| Мобильный интернет (то же) | то же | `401` |
| С хоста Caddy, подделка внешнего клиента | `curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: <BASE_DOMAIN>' -H 'X-Forwarded-For: 203.0.113.9' http://<SERVER_ADDR>/api/info` | `401` |
| С любого LAN-хоста напрямую на сервер, подделка заголовка (только если сервер слушает `0.0.0.0`) | `curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: <BASE_DOMAIN>' -H 'X-Forwarded-For: 10.1.1.50' http://<SERVER_ADDR>/api/info` | `401` |

Если хоть один из ответов `401` получился `200`, сразу закомментируй `TAMSYAM_PRIVATE_NETWORKS`, перезапусти сервис и сообщи пользователю. Открытая админка показывает заголовки запросов, включая cookies и `Authorization`.

Чтобы отключить беспарольный вход, закомментируй `TAMSYAM_PRIVATE_NETWORKS` и перезапусти сервис.

## Пароль админки

Пароль один, логин может быть любым (HTTP Basic). Он задаётся в `TAMSYAM_ADMIN_PASSWORD`.

Смена пароля (с согласия пользователя):
```bash
cp -p /etc/tamsyam/server.env /etc/tamsyam/server.env.bak.$(date +%s)
NEW=$(openssl rand -base64 24 | tr -d '/+=')
sed -i "s|^TAMSYAM_ADMIN_PASSWORD=.*|TAMSYAM_ADMIN_PASSWORD=$NEW|" /etc/tamsyam/server.env
unset NEW
systemctl restart tamsyam-server
```
**Готово, когда** запрос с новым паролем (`PW` перечитан из файла) к `/api/info` даёт `200`, а без пароля извне — `401`. Пользователю скажи, что пароль сменён и лежит в `/etc/tamsyam/server.env`. Сам пароль покажи один раз, только если пользователь попросил.

**Защита от перебора.** После 10 неверных паролей или токенов за 15 минут сервер блокирует IP до конца этого окна. На все запросы этот IP получает `429` с заголовком `Retry-After`, даже если пароль верный. В журнале остаётся строка `too many failed logins, client blocked`. Блокировки хранятся только в памяти, поэтому рестарт сервиса их снимает. Если в журнале блокируется адрес Caddy, значит, не настроен `TAMSYAM_TRUSTED_PROXIES`: все клиенты выглядят одним IP и блокируются вместе.

Если старый пароль где-то засветился (в чате, скриншоте, логе), смени его, даже если это было давно.

## Токены клиентов

Токены хранятся в базе в виде sha256-хэша. Секрет вида `tsm_…` показывается один раз, при создании.

- Создать: `curl -s -u "admin:$PW" -H 'Content-Type: application/json' -d '{"name":"<кому>"}' https://<BASE_DOMAIN>/api/tokens`. Поле `secret` передай пользователю один раз. Себе для проверок держи токен в файле с правами `600`, а не в чате.
- Список: `GET /api/tokens`. Отозвать: `DELETE /api/tokens/<id>`. Активные туннели отозванного токена продолжают работать до переподключения. Чтобы оборвать их сразу, отключи туннели через `DELETE /api/tunnels/<key>`.
- Пробные токены, созданные для проверок, отзови в конце работы.
